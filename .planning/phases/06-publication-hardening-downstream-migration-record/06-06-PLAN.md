<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fork PR -> CI jobs | contributor-controlled code runs under the repo's read-only token |
| GitHub Apps -> repo (rulesets, releases) | App tokens minted per run; protection and release are separate Apps |
| publish jobs -> PyPI / TestPyPI | OIDC identity = repo + workflow filename + environment |
| third-party actions -> runners | code fetched by sha |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-14 | Tampering | third-party actions | high | mitigate | every `uses:` pinned to a 40-char sha (kit floor); verify step greps for non-sha refs; setup-uv sha confirmed via gh api |
| T-06-15 | Elevation of Privilege | job permissions | high | mitigate | kit's job-level `contents: read` (+ `pull-requests: read`) on all three required contexts; release-please.yml `contents: read` with App token; no write scope on lint |
| T-06-16 | Elevation of Privilege | pull_request_target / job-level if / trigger filters | critical | mitigate | grep gates in verify; conditionality only on steps via classify-changes |
| T-06-17 | Spoofing | publish identity | high | mitigate | environments `pypi` / `testpypi` distinct; check_publish_gate.py containment check runs in the lint job |
| T-06-18 | Information Disclosure | App private keys / Codecov token | high | mitigate | only referenced as `${{ secrets.* }}`; never echoed; protection and release credentials are different secret pairs |
| T-06-SC | Tampering | uv build / actions supply chain | high | mitigate | uv from setup-uv sha; deps from hash-pinned uv.lock; no pip on runners |

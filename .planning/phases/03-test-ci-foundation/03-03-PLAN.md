       part of the safety net; a lock-drift regression fails CI). `dev` group installs by

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted PR → CI runner | `pull_request` from a fork runs workflow code on GitHub-hosted infra |
| pinned action → CI runner | third-party GitHub Actions execute in the job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Information Disclosure | CI job on `pull_request` from forks | medium | mitigate | The job uses NO secrets (codecov/token deferred to Phase 6), so a fork PR has nothing to exfiltrate; default `GITHUB_TOKEN` is read-only for fork PRs. `coverage.xml` is uploaded as a plain artifact, not to a token-gated service. |
| T-03-03 | Tampering | third-party GitHub Actions (setup-uv, checkout, upload-artifact) | low | accept | Pin to current immutable version tags (`@v8.3.2`, `@v5`, `@v4`) per RESEARCH §3. Full SHA-pinning (pchandler-style) is an explicit Phase-6 publication-hardening concern (D-09 reconciliation); acceptable to defer for this lightweight phase. |
| T-03-SC | Tampering | `uv sync --frozen` install in CI | medium | mitigate | CI installs strictly from the committed hash-pinned `uv.lock` (`--frozen`); a lock-drift or substitution fails the job rather than resolving fresh. |
</threat_model>

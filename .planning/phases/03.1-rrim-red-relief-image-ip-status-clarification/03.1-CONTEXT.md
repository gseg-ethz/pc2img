# Phase 03.1: RRIM (Red Relief Image) IP status clarification - Context

**Gathered:** 2026-07-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Resolve the blocking IP/publication gate on `src/pc2img/features/rrim.py` (RRIM =
Red Relief Image Map) so the library can be pushed to its public remote safely
and Phase 3's live-CI UAT can proceed.

This is a **legal-status investigation + disposition-execution** phase, not
feature work. RRIM is associated with third-party prior-art patents (reported:
Asia Air Survey Co., Ltd. — unconfirmed) and has not been legally investigated.
Because `rrim.py` is already committed on the private phase branch and git
*history* carries the file, any public push would be its first public exposure —
so the gate must be resolved **before** the first push, and removal (if needed)
is a history-level decision, not a working-tree delete.

**This phase must:** investigate the IP status, decide a disposition, and execute
that disposition in-tree (and in history if required) — leaving the branch in a
provably publication-safe state.

**Not in scope:** the Phase 4 code-quality/correctness review of `rrim.py`
(separate concern); general publication-hardening / branch-protection (Phase 6).

**Note on legal authority:** neither the owner nor Claude is a lawyer; this phase
produces a good-faith, documented risk assessment and an executed disposition —
not a binding legal opinion. Where the disposition depends on a license grant, an
external confirmation (rights-holder / ETH tech-transfer) may be required and is
called out as a research question below.

</domain>

<decisions>
## Implementation Decisions

### Definition of Done
- **D-01:** Phase 03.1 delivers **findings + decision + executed disposition** —
  the heaviest option. Concretely: (1) an IP findings document, (2) an ADR
  recording the chosen disposition with rationale, and (3) the disposition
  actually carried out in the tree (and in branch history if removal is the
  outcome). "Done" means the gate is cleared and the branch is publication-safe.

### Disposition Decision Rule
- **D-02:** The disposition is **findings-driven**, not pre-committed. Investigate
  the patent(s), jurisdiction(s), claims, expiry, and — critically — license
  availability before executing.
- **D-03:** **Preferred lean — keep + gate + license/attribution notes.** Early
  signal suggests a research/educational license may be obtainable from the
  rights-holder. If such a license permits public redistribution under pc2img's
  own license, keep RRIM in the package behind an explicit opt-in extra with a
  prominent NOTICE/CONTRIBUTING legal note and attribution.
- **D-04:** **Fallback — separate optional package.** If a research/educational
  license exists but does NOT clearly permit public redistribution inside the
  main pc2img distribution (PyPI, all users, permissive repo license), pull RRIM
  out of the main distribution into a separate opt-in plugin/package governed by
  that license, so main-package users are not auto-distributed the code.
- **D-05:** **Floor — strip from tree + history.** If no viable license basis
  exists at all, remove `rrim.py` + its test from the tree and rewrite them out
  of the branch's history (filter/rewrite, not a delete commit), and remove RRIM
  from the public feature set. Cheapest to do now (private branch, no remote).
- **D-06:** Rationale for rejecting a naive in-package gate as a *cure*: gating
  alone does not cure a distribution/history risk — shipping the code in the
  published package/history distributes it regardless of opt-in. A gate is only
  valid when paired with a redistribution-permitting license basis (D-03);
  otherwise D-04/D-05 apply.

### Phase 3 UAT Sequencing
- **D-07:** **Resolve-then-push (sequential).** Phase 3's live-CI UAT stays
  BLOCKED until 03.1 fully executes the settled disposition; then a single clean
  push of the settled branch satisfies the UAT. The project accepts an external
  wait (license confirmation) rather than a decoupled interim push.
- **D-08:** Consistency observation for the planner: current-unlicensed RRIM does
  not survive in the main public package under ANY disposition branch (it is
  gated-with-confirmed-license, relocated, or stripped). The single post-
  resolution push is therefore always into a provably-safe state.

### Disposition Resolution (post-research, 2026-07-10)
These resolve the findings-driven disposition (D-02) after RESEARCH.md landed
(patent-expiry findings). They are **forward-only additions** that supersede the
*openness* of the earlier decisions where noted; D-01..D-08 are retained as the
reasoning trail, not overwritten.
- **D-09 (disposition = D-03, keep + NOTICE):** RESEARCH.md confirms the core RRIM
  patent (Asia Air Survey / Tatsuro Chiba — e.g. US 7,764,282 B2, JP 3670274,
  CN 1711568B, TW I285852) is **expired in every jurisdiction** (US adjusted
  expiry 2025-10-05). RRIM is therefore kept on a **patent-expiry basis** with an
  expiry-basis legal NOTICE + AAS attribution — **no license acquisition
  required**. This commits D-02's open choice to **D-03**; D-04 and D-05 are NOT
  executed. `rrim.py` reads on the now-expired core claim but not on the two
  still-active AAS patents (both require a stereoscopic/super-resolution step this
  flat-RGB implementation lacks).
- **D-10 (D-07 external wait collapses to internal sign-off):** Because expiry
  removes the AAS-license dependency, the D-07 ETH tech-transfer step downgrades
  from a *blocking external license-wait* to a **good-faith ETH/owner sign-off
  documented in-repo**. No external dependency blocks the phase; the settled
  branch is publication-safe once the disposition executes, and Phase 3's live-CI
  push proceeds without an external wait. This refines D-07/D-08.
- **D-11 (exposure = opt-in extra + NOTICE):** RRIM stays loadable via an explicit
  opt-in `rrim` extra carrying the NOTICE (matching D-03's gate language, using the
  existing pyproject extras pattern as the analog). The module is **not** wired
  into the default public feature barrel (`features/__init__.py`). The docstring's
  advertised `generate(["rrim", ...])` API is reconciled to state the opt-in path.
- **D-12 (trademark = keep name + attribution):** Keep the "RRIM" / "Red Relief
  Image Map" name under nominative/descriptive use with clear AAS trademark
  (RRIM®) attribution in the NOTICE. **No rename** of the feature or its DSL key.

### Claude's Discretion
- Exact structure/filename of the findings doc and ADR, and the mechanical
  approach to any history rewrite (e.g. `git filter-repo` vs interactive rebase),
  are left to research/planning — provided the outcome matches D-01..D-08.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- The disposition machinery is mostly git + packaging, not new pc2img code:
  optional-extra wiring already exists in `pyproject.toml` (cuda11/cuda12 extras
  + PEP 735 groups) as a pattern for a `rrim` opt-in extra if D-03 is chosen.

### Established Patterns
- `rrim.py` registers via `@FEATURES.register` decorators that only fire when the
  module is imported. It is **not** imported by `src/pc2img/features/__init__.py`,
  so RRIM is not currently part of the public feature barrel — it is loaded only
  by its test. This means gating/removal does not require unwiring a public
  import today, but the docstring's advertised public API should be reconciled
  with whatever disposition is chosen.
- Feature registration side-effects at import time (per project conventions) mean
  a "separate package" (D-04) can re-register RRIM by importing its module.

### Integration Points
- CI: the scoped pytest suite currently collects `tests/test_rrim_features.py`;
  any strip (D-05) or relocation (D-04) must keep the suite green (remove/move the
  test with the module) so Phase 3's coverage baseline and CI stay consistent.
- History: because removal is a history-level action, the planner must treat the
  branch-history rewrite as a first-class task, sequenced before the D-07 push.

</code_context>

<specifics>
## Specific Ideas

- Owner's early read: "there are possibilities to license for educational/
  research, which would probably point to gate + license notes" — this is why
  D-03 is the preferred lean and D-04 (separate package) is the redistribution
  fallback rather than an immediate strip.

## Load-bearing research questions (decide the whole disposition tree)
1. **Patent identity & status:** which patent(s), which jurisdiction(s), which
   claims, filing/priority and expiry dates? (RRIM ~2002–2005 filings may be at
   or near 20-year expiry — CONFIRM, and confirm holder Asia Air Survey.)
2. **Infringement read:** does this image-space NumPy implementation
   (slope→red + (positive−negative) openness→structure) plausibly read on the
   asserted claims? (good-faith, non-binding)
3. **Redistribution rights:** does any obtainable research/educational license
   permit redistribution inside a public, permissively-licensed PyPI package to
   all users (incl. commercial)? This is the D-03-vs-D-04 pivot.

</specifics>

<objective>
Close G1-WR-01 and G1-IN-01, and correct the store docstrings they touch. 07-13's `_has_on_disk_artefact` sends any untracked key with ANY of six derived files into `purge`, and upstream `purge` checks the owner pid before it checks existence. So a harmless leftover — a `<key>.dat.tmp` from a killed worker, a lone `<key>.dat` from a `purge_disk_on_gc=False` session (iof3D's durable warm restart), a lone `<key>.meta.json` — makes every non-owner process refuse the key with `StorePurgeRefusedError`: deterministic at `n_jobs=1` after a pooled run, random in a pool. Planner reproduction 2026-10-02 on HEAD `7094dde`, forked non-owner child: refused (exit 3) for all five leftover kinds. Measured adoption rule of the base store's startup scan (same session): a lone `<key>.npy` is adopted (tracked; the read is a cache miss), a lone `.meta.json` is not, a lone `.dat` is not, the pair is served. So only `<key>.npy` can make a fresh store serve a stale raster.

The fix has two halves, because the owner's two instructions pull in different directions on one file type: the stale-serving set is `<key>.npy` alone, but 07-13's retained-reference GC test (which must stay green) protects a key whose only file is `<key>.dat` — the hazard there is the dropped entry's armed finalizer in THIS process, and `purge` is the only route that detaches it. Resolution, validated by the planner's prototype: (hard) a tracked key or an on-disk `<key>.npy` purges unconditionally (refusals propagate — a non-owner may not remove a stale pair); (soft) a lone `<key>.meta.json` or `<key>.dat` attempts `purge` and tolerates exactly the process-identity refusal (nothing servable is on disk, and the replacement's write supersedes the leftover atomically) while any `StorePurgeRefusedError` subclass — foreign or aliased artefact — still propagates; temporary names are not consulted at all (writers overwrite them). With that shape the non-owner child succeeds on every leftover kind except the codec pair, the owner-process GC variant stays green, and the gate shrinks from six hand-copied builders to three.

Purpose: a reused tiled instance (or any unpickled store copy) must not turn crash residue or a durable `.dat` into a hard random failure; the hand copy of upstream's artefact set shrinks to what carries correctness weight and is pinned.

Output: the narrowed gate; forked-process regression tests red on HEAD; the builder-shape pin; corrected docstrings with an AST proof.

Gap-round ordering: this is gap round 2; it runs before the paused 07-07 resumes and does not touch the paused 07-15. Wave numbers are gap-round-local (07-16 and 07-17 are wave 1, 07-18 is wave 2); nothing here runs in parallel with 07-07 or 07-15.

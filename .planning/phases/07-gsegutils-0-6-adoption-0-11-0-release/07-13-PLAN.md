<objective>
Close CR-02 and WR-05, and document the store half of WR-01. `add_image_to_store` purges only `if img_name in self`, and upstream `__contains__` reports tracking only. Since 0.11 `del`/`pop`/`clear` drop tracking and leave `<key>.npy` + `<key>.meta.json` on disk, so a re-add after any drop route skips the purge: the old codec pair survives, a fresh store adopts it and serves the pre-overwrite raster as a cache hit (feature names are cache keys, so nothing downstream can tell). The same skipped purge leaves the dropped entry's finalizer armed, and a retained reference to it deletes the replacement's `<key>.dat` on garbage collection. Fix: purge whenever the key is tracked OR any of its six upstream-built artefact paths exists — checked in pc2img before calling `purge`, because upstream's `purge` runs its owner-pid guard BEFORE its existence check, so calling it unconditionally (the review's `suppress(KeyError)` sketch) would refuse every brand-new key added inside a loky worker that did not construct the store.

Purpose: silent wrong output on the warm-restart path for any caller of the publicly exported store (the caller BC-P2I-027 addresses), plus a GC-time deletion attributable to nothing in the caller's code. Owner disposition (2026-10-02): fix now; cover the GC variant; keep `del`/`pop`/`clear` drop-tracking-only.

Output: presence-gated purge in `disk_backed_image_store.py`; regression tests red on the pre-fix code and green after; docstrings corrected (WR-05, WR-01 store half) with a docstring-only AST proof.
